# Inventory of installed skills and how they're used

- **Ticket:** weareit-app/weareit#142, part of the map #140 (repo conventions that enforce themselves)
- **Checked:** 2026-10-21, against `origin/master` (1dced8f).
- **Scope:** facts only. The skills grilling ticket (#151) makes the decision.

## Summary

- 41 skills are installed in each of `.claude/skills/` and `.agents/skills/`: 27 vendored from Matt Pocock's skills, 6 generated by OpenSpec, and 8 written for this repo (4 `pains-*`, 4 `possibilities-*`). `.claude/commands/opsx/` adds 6 OpenSpec slash commands for Claude Code only.
- The 27 vendored skills are byte-identical to upstream `mattpocock/skills` at 5beb35b, and identical between the two folders.
- The folders differ in 8 files. In 6 OpenSpec skills this is by design: the generator writes each tool's invocation syntax. In `pains-ingest` and `pains-review` the `.agents/` copy is stale: four commits on 2026-10-20 changed only the `.claude/` copy.
- In the session logs (2026-10-17 to 2026-10-21), 16 of the 41 skills were invoked at least once. The most used are `code-review`, `pr`, `tdd`, `grilling`, `research`, `domain-modeling`, and `writing-for-agents`. 18 skills show no invocation and no mention in a typed prompt.
- Several vendored skills expect paths this repo doesn't have: `docs/adr/`, `.scratch/`, and `.out-of-scope/`. `docs/agents/domain.md` already redirects decision records to `docs/architecture/decisions.md`, but the skills' own text still says `docs/adr/`.

## How this was checked

- **Folders:** `diff -rq .claude/skills .agents/skills`, and `git log` on each folder.
- **Upstream:** fetched `github.com/mattpocock/skills` at 5beb35b040e3de97e54fa9e386d7e42d15c295c2 and ran `diff -rq` on each of the 27 skill folders (`skills/engineering/*` and `skills/productivity/*`) against `.claude/skills/<name>`. No differences.
- **Session logs:** 306 `.jsonl` files in the 42 `~/.claude/projects/` folders whose names contain `weareit` (the main checkout and its worktrees; subagent logs included). Timestamps run from 2026-10-17 to 2026-10-21. Two kinds of use are counted:
  - **slash:** a `<command-name>` tag in a user turn (a person, or another session's brief, typed `/name`).
  - **tool:** an assistant `Skill` tool call with that skill. This includes calls one skill makes for another (for example `/implement` calls `tdd` and `code-review`).
  - For skills with no hits, user turns under 4,000 characters were also searched for `/name` or `$name` in prose.
- **Codex logs:** 19 of the 34 files under `~/.codex/sessions/` mention `weareit`, all from 2026-10-20. None reads a `skills/<name>/SKILL.md` file.
- **PRs and commits:** the bodies of all 60 PRs (`gh pr list --state all`) and every commit message (`git log --all`) were searched for `/name` and `$name`.

The counts are a lower bound. A skill that was read but not invoked (for example through `Read`) isn't counted, and logs before 2026-10-17 aren't on this machine.

## Overlaps

- **Writing a spec:** `/to-spec` publishes a spec as a GitHub issue; `/opsx:propose` writes `openspec/changes/<name>/`. `AGENTS.md` makes OpenSpec the spec home and says `/to-spec` "is not the spec home". `ask-matt`'s main flow still sends multi-session builds through `/to-spec`.
- **Tracking tasks:** `/to-tickets` makes GitHub issues with blocking edges; an OpenSpec change tracks work in `tasks.md`. `AGENTS.md` limits `/to-tickets` to handing task groups to parallel sessions, one issue per group.
- **Implementing:** `/implement` (one spec or ticket), `/implement-spec` (a `to-spec` spec and its tickets, in parallel), and `/opsx:apply` (an OpenSpec change's tasks). `AGENTS.md` pairs `/opsx:apply` with `/tdd` or `/implement`. `/implement-spec` depends on the `to-spec` output this repo doesn't use.
- **Interviewing:** `/grill-me` and `/grill-with-docs` are one-line wrappers: the first calls `grilling`, the second calls `grilling` and `domain-modeling`. Wayfinder grilling tickets also call those two. `/opsx:explore` is a separate, looser thinking-partner mode.
- **Decision records:** `domain-modeling`, `grill-with-docs`, `improve-codebase-architecture`, and `setup-matt-pocock-skills` say `docs/adr/`. `docs/agents/domain.md`, `AGENTS.md`, and the map say `docs/architecture/decisions.md`. `docs/agents/domain.md` still draws `docs/adr/` in its own file-structure diagrams.
- **Architecture:** `codebase-design` is the vocabulary; `improve-codebase-architecture` applies it in a scan, then grills.
- **Standards:** `code-review` enforces `CODING_STANDARDS.md`; `retro` proposes additions to it, and sends mechanical rules to checks instead.
- **Syncing specs:** `/opsx:sync` merges deltas without archiving; `/opsx:archive` also syncs before it archives.
- **Handing off:** `/handoff` writes a file to `$TMPDIR`. The Claude desktop app's own session hand-off does similar work, outside the repo.
- **Planning large work:** `/wayfinder` maps decisions as issues; its destination here is an OpenSpec change, so the two run in sequence rather than in parallel.
