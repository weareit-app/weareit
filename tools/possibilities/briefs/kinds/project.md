# Project brief: a bounded effort with an end

Read `briefs/kinds/_shared.md` first. This brief covers only Project fixes (`kind: project`, origin `kind:project`).

A Project is an effort over days or weeks, with several steps and an end: a block party, a tool-lending shelf, a four-day-week trial at work. Its title names the finished thing.

## Method

Three methods shape a Project:

- **More than one action** (Getting Things Done). Any outcome that takes more than one action is a project. If one action finishes it, it's a Task.
- **A definition of done** (the Scrum Guide). Say what must be true for the work to be finished. A Project without a done state is an ongoing effort, which is usually a Group.
- **Output versus outcome** (the W.K. Kellogg Foundation's logic model). The finished thing is the output ("we held a repair night"). The change in people is the outcome ("neighbors kept their appliances"). The title names the output; the text says why it matters.

For each accepted dream with a Project ceiling above zero, list bounded efforts that would move a person toward it. Check each has an end and a handful of steps. Keep only the strongest, up to the ceiling.

## Method fields

Fill these in `method` before writing any copy:

| Field | What it holds |
| --- | --- |
| `finishedThing` | What exists at the end ("A tool-lending shelf in the laundry room, with a sign-out sheet.") |
| `doneWhen` | When it's done ("Neighbors have borrowed from the shelf.") |

You may also add `duration` (roughly how many days or weeks), `steps` (three to six, to check it's really bounded), and `withWhom`. None is required. Only the first step goes in the copy.

## Is it really a Project?

| If… | then it's… |
| --- | --- |
| one action finishes it | a Task |
| it has no end and people keep coming back | a Group or New group. Starting a group can feel like a project, but the kind follows what lasts. |
| it repeats on the calendar | a Schedule |
| it depends on a decision-maker saying yes (a campaign for a local rule) | an Ask, not a Project. Leave it out. |
| it's something It would build | a Feature |

A Project's status is usually `real_now`.

## Examples

Good:
- **Title:** "Organize a tool-lending shelf in your building's laundry room"
- **Text:** "Putting up a shelf, a sign-out sheet, and a dozen spare tools from neighbors is a weekend's work, and neighbors start talking to each other over it."
- **Method:** `finishedThing` "A tool-lending shelf with a sign-out sheet in the laundry room.", `doneWhen` "Neighbors have borrowed from it.", `duration` "One weekend", `steps` ["Ask the building manager about the space.", "Collect spare tools from neighbors.", "Put up the shelf and the sheet."].
- **Lens and ambition:** `community`, `this-year`.

Bad:
- **Title:** "Build community in your building"

There's no finished thing and no end. This is a dream, not a Project.
